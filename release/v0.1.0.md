## 新增

**产品模型**（参考 titanwings/dsh-automation，按 kcoder 0.1.6-alpha.1 框架能力原生重写）

- 把「完整可自足」的编码任务按时间计划投递到**全新根 Agent 会话**独立执行：
  不继承创建它的对话历史、收件箱、授权或过往审批；运行历史持久可审计。
- 四种时间计划：一次性（ISO 时刻）/ 固定间隔（≥5 分钟，锚定节奏不受 DST 影响）/
  每天 / 每周（周一到周日任选），daily/weekly 使用 IANA 时区本地 `HH:mm`；
  DST 不存在的墙面时间**跳过而不是平移**（luxon 求解）。

**调度与恢复语义**

- Cordis 时钟 + 确定性 occurrence key + 持久游标：同一到期 occurrence 至多派发一次。
- 宽限窗口（默认 15 分钟）内只有**最新**一个到期 occurrence 补跑；更早的不回放。
- 同一任务同时至多一个 queued/running；到期 occurrence 记 `skipped(overlap)`。
- 运行超时（默认 60 分钟）取消并记 `failed`；宿主重启把 queued/running 记
  `failed(host_interrupted)`，绝不秘密重跑。
- 每任务终态历史保留上限 200（可配）；活跃记录永不裁剪。
- 全局并发闸 `maxConcurrentRuns`（默认 2）。

**执行边界（无人值守信任）**

- 两档权限：`read-only` / `workspace-write`；不接受无人值守 full access。
- `approval policy = never`：仍需交互审批的工具直接失败（fail closed）。
- 明确能力允许清单：bash/pwsh（禁后台）、读写检索、web、skill、会话检索在列；
  交互提问、计划、目标、嵌套 Agent、后台任务、递归自动化管理一律拒绝。
- 沙箱模式与审批策略在 Agent 发布前安装；任务消息带 `source.kind = automation`
  （automation/run 身份 + 计划时刻），从不冒充人类消息。
- 无自动副作用重试：手动「立即运行」是唯一的重试路径。

**Web 控制页（双入口之一）**

- 侧边栏「定时任务」菜单项：官方 `sidebar.panellist` slot（shell 拥有按钮/Tooltip/
  active 态，插件只出图标字形），无 DOM hack。
- 独立管理页面：官方 `main` keyed slot，不依赖会话视图——任务列表、创建/编辑、
  暂停/恢复/删除/立即运行、运行历史（状态/耗时/摘要/错误/跳过原因）、打开结果会话。
- 创建表单：自包含提示词、四种计划、IANA 时区（常用区 datalist + 自由输入）、
  **绑定工作区自选**（默认当前会话工作区，可改选任意已注册工作区；cwd 一律由
  服务端 registry 解析）、权限边界、模型目标（跟随全局 / 钉住 provider+model+
  推理力度，目录经 `ctx.remote.session` 命名空间加载并解包 Typert 信封）。
- 工具栏跨工作区过滤（全部工作区 / 单工作区），任务与历史随选过滤。
- zh/en 双语；3 秒可见性轮询（隐藏页暂停读取）。
- **双主题自适应**：全部颜色走宿主 design-platform alias token
  （`--dsw-alias-label-*` / `bg-*` / `border-*` / `state-*`，浅色 `:root` 与
  深色 `body[data-ds-dark-theme]` 自动切换），徽章/状态色用 `color-mix` 派生
  半透明填充；无 token 的宿主回落浅色字面值。
- RPC 通道 `/dsh-kylin-automation`：直挂注入的 webServer，复刻 connection 传输
  语义（同一 Host/Origin + 浏览器鉴权围栏 `connection.requestRejection`、
  client-request/server-response 信封、4MB 体积上限）。

**Agent 工具（双入口之二）**

- `automation_create` / `automation_list` / `automation_update` /
  `automation_run_now` / `automation_runs` / `automation_delete`：
  按调用者会话 cwd 绑定工作区，不接受任意路径；工具结果含下次运行时刻、
  最近运行与运行历史（有界摘要）。
- 创建/更新/立即运行/删除经 `tools/pre-execute` 提升人工审批；
  **仅 status=paused 的单独暂停豁免**。
- systemPrompt 能力通告 section（工具面 + 三要素提示词约定）。

**部署形态**

- Host ESM bundle + Web client bundle 双产物；`@deepseek-ai/*` 零运行时导入
  （KCoder 打包运行时不向插件提供框架模块——框架能力全部经 inject 服务名接入）。
- client bundle 走 `window.__ModuleLoader__.load({ id, factory })` 自注册协议，
  react 经宿主静态模块表 require。
- 安装渠道：npm registry / GitHub 独立仓 / dsh-plugins 镜像仓子目录。
- 发布链：`pnpm check` + `node scripts/smoke-plugin.mjs`（manifest/patch/bundle/
  ModuleLoader 契约冒烟）→ `release/vX.Y.Z.md` → npm publish → GitHub Release
  （`scripts/create-github-releases.mjs`）→ dsh-plugins 镜像同步（`--check` 对账）。

## 兼容性与升级说明

- 需要 DSH ≥ 0.1.6-alpha.1（官方 `sidebar.panellist` / `main` keyed slot 与
  `ToolDefinition.output` 契约）。
- 配置经 bundle 自带 `cordis.patch.yml`（`maxConcurrentRuns: 2`、
  `runTimeoutMinutes: 60`、`misfireGraceMinutes: 15`、`historyLimit: 200`），
  编辑部署 profile 的 bundle 行即可调整。
- 定时任务按**工作区**隔离：创建时绑定一个已注册工作区；快照与列表随当前
  会话定位，Agent 工具严格绑定调用者 cwd。
- 已知限制（v0.1 明确不做）：同会话心跳（请用 DSH Core Schedule）、原生 cron、
  无人值守 full access、运行结果确认/重试闭环、多工作区 DAG、外部投递、
  外部副作用的恰好一次保证。
