## 新增

- **QiLin（麒麟）引擎双通道适配**：
  - manifest 新增 `qilin.bundle.patch` / `qilin.client` 原生通道，与既有
    `dsh.*` 指向同一份 `cordis.patch.yml` 与 client 交付物，行为完全一致。
    QiLin（dsh 0.1.6-alpha.2 合并后）的插件管理器只认原生键
    `qilin.bundle.patch`（缺失报「没有声明组合包」），DSH 宿主仍读 `dsh.*`。
  - 新增 13 个 `@deepseek-ai/*` 引擎包 `peerDependencies`（`*`）：按框架契约
    由宿主安装副本统一解析（dsh alpha.2 起依赖解析默认运行时模式）。
  - README 新增 QiLin 安装方法（npm registry / GitHub 直装）与注意事项：
    必须经 `qilin plugin add` 装进 profile 私有
    `~/.qilin/profiles/<name>/node_modules`（共享 `profiles/node_modules`
    为安装保留区，bundle 层包放那里激活直接 `failed to import`）；运行需
    QiLin 3.0.0+（带 dsh 兼容层），插件管理（设置页展示/启停）需 3.0.2+。

## 变更

- **dispose 生命周期加固**（插件停用 / HMR 场景，插件管理器 dispose 后
  `pnpm remove` 包目录）：
  - 新增 `runAbort: AbortController`：dispose 先 abort，在途 agent 会话走
    取消路径，不再空烧 token 直到超时；`executeAutomationRun` 接线 executor
    既有的 `signal` 支持。
  - 新增 `executions` promise 注册表（原 `execute` 拆出 `executeInner`）：
    dispose 经 `Promise.allSettled` 排空全部在途 run 后才关 store，终态写盘
    不会落进已关闭的 storage domain。
  - 终态 `updateRun`（含 startedAt 写入）包 `.catch`：dispose 竞态下记账
    失败不升级为 unhandled rejection，残留记录由 dispose 兜底扫描标为
    `host_interrupted`。

## 修复

- **定时任务永不自动调度**（重要）：
  - 症状：按计划创建的定时任务从不自动执行，只有 `automation_run_now`
    手动路径可用。
  - 根因：`apply()` 打开 service 后从未调用 `start()`，时钟未启动
    （`alive=false`），`requestTick` 直接返回，调度循环空转。
  - 修后行为：`apply()` 显式 `service.start()`——时钟启动 + 崩溃恢复
    （durable queued/running 记录标 failed(host_interrupted)），定时
    occurrence 正常派发。

## 兼容性与升级说明

- DSH 宿主（`dsh.*` 通道）：行为不变，直接升级。
- QiLin 宿主：运行要求 QiLin 3.0.0+（带 dsh 兼容层）；插件管理（设置页
  展示/启停）要求 3.0.2+。安装必须经 `qilin plugin add`（npm 包名或
  `github:kkutysllb/dsh-kylin-automation`）。
- 自 0.1.0 / 0.1.1 直接升级无破坏性变更；定义/运行历史数据与 RPC 契约
  不变。
- KCoder（link 安装）：重启宿主后生效（client bundle 的 rev 在宿主启动时
  固定，仅刷新页面拿不到新 bundle）。
