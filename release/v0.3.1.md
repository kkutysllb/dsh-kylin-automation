## 背景

宿主本地 fork 升到 **kcoder / dsh 0.1.7-rc.2**（2026-09-25 尖端
`323be30855`）。本轮不是「坏了要修」，而是**主动对齐**：先把 0.1.7 窗口
（alpha.1 → rc.2）里与本插件消费面相交的契约逐条比对，再只采用确有价值的
那些。审计全表见仓库 README「宿主兼容性基线」一节。

## 新增

- **审批 ask 的双文案契约（`humanApprovalAsk`）**：
  - `reason` 与 `displayReason` 分离——前者是随审批请求落审计日志的
    **与语言无关**的文案，后者是审批卡按界面语言渲染的提示文案。
  - 四个变更动词（create / update / run_now / delete）各有独立说明，
    不再共用一句通用提示。
  - `displayReason` 提供 `en` 与 `zh` 两个键；`ui-approval` 经
    `locale.resolveText` 解析，缺键回落 `en`。
  - 旧宿主不认识该字段：多余属性被忽略、审批卡回落 `reason`——**向后兼容**。
- **`automationNoticeSource()`**：把定时任务提示消息的消息源构造抽成纯函数
  （`kind:'automation'` + `form:'notice'` + 有界摘要），可单测。
- 新增 `tests/executor.test.ts`（4 个用例）：消息源形态、摘要上限与身份保留、
  无人值守允许清单。

## 变更

- **能力公告段瘦身 512 → 407 字（−20%）**：对齐 rc.2 的提示词预算策略
  （该版净删 3658 行提示词/工具描述，标准预设首轮提示 −18%）。逐条参数规则
  （计划种类、时区必填、权限枚举、modelTarget 语义）从系统提示词移除——
  它们已经在工具参数描述里。公告只保留：六个工具名册、三条非显然约束
  （任务自包含 / 先 run_now 验证 / 变更需人工审批）、Web 入口。
- **notice 摘要收敛到框架上限 120 字**（`CONTEXT_SUMMARY_MAX_CHARS`）。摘要
  用于折叠的对话行；名字超长时先压缩**名字**，run 身份（`krun-…`）保持完整
  可读，最后再套框架上限兜底。
- `src/types/dsh.d.ts` / `src/client/contracts.ts` 的契约注释改按
  **0.1.7-rc.2** 口径，并新增 `PreToolDecision` 的 ask 变体声明。
- `package.json` 版本 0.3.0 → 0.3.1。

## 修复

- 无。本轮未发现本插件在 0.1.7-rc.2 下的失效面。

## 删除

- 导出 `humanApprovalReason(toolName): string` 被 `humanApprovalAsk(toolName)`
  取代（返回 `{ reason, displayReason }`）。它从未是文档化 API，仓内唯一
  消费点（`tools/pre-execute` 钩子）与测试同步更新。

## 兼容性与升级说明

- 自 0.3.0 直接升级无破坏性变更；定义与运行历史数据、RPC 契约、工具
  契约、客户端槽位注册均不变。
- **插件 peer 兼容门**：0.1.7 起宿主在启动 / bundle 加载 / 安装三处按
  `peerDependencies` 强制校验 `@deepseek-ai/dsh*`。本插件全部声明为 `*`，
  判定放行；**刻意不收窄**——① `^0.1.7` 这类裸 minor 在 `includePrerelease`
  下展开后不含预发布比较器，反而会拒绝 `0.1.7-rc.2`；② QiLin 通道报告的
  运行时版本不保证是 dsh semver。
- 变更仅在宿主侧生效需重启 `dsh web`（或 KCoder）后生效（client bundle 的
  rev 在宿主启动时固定）。
